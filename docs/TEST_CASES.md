# Тест-кейсы: станция + Kontakt Mesh, фаза 1

**Блокирующие (B)** — если не проходит, стадию не принимаем.
**Критические (C)** — серьёзный дефект, но стадию можно принять с задачей на исправление.

Каждый ожидаемый результат проверен на стенде перед тем, как попасть сюда. Колонку
«Итог» заполняете вы: ✅ / ❌ + что увидели.

## Подготовка (один раз)

```bash
git pull
go build -o bin/ ./cmd/...                 # web, signal, media, loadgen, kontakt-node
```

Две части стенда — их можно держать запущенными одновременно, порты не пересекаются:

| Что | Команда | Порты |
|---|---|---|
| Станция (рулетка) | `IP=<IP машины> SIP_UDP=:5060 ./scripts/run.sh` | web `:8080`, signal admin `127.0.0.1:8091`, media `127.0.0.1:8082`, SIP `:5060` |
| Mesh (Master + 5 Worker'ов) | `./scripts/mesh-demo.sh` | Master admin `127.0.0.1:7401`, Worker'ы `127.0.0.1:7421…7425` |
| Мониторинг (по желанию) | `docker compose -f monitoring/docker-compose.yml up -d` | Grafana `http://localhost:3002` |

NodeID узла демо-стенда: `bin/kontakt-node -identity data/mesh-demo/w3.key -print-id` (w1 = vps-almaty,
w2 = home-router, w3 = office, w4 = phone-termux, w5 = vps-bishkek). PID узла — в выводе
`mesh-demo.sh`.

### B-2. Два человека соединяются и слышат друг друга
- **Шаги:** открыть `http://localhost:8080` в **двух разных браузерах** (или обычное окно +
  инкогнито). В первом «Снять трубку», подождать 3 с. Во втором «Снять трубку». Говорить.
- **Ожидается:** первый, пока один, слышит гудки; после снятия трубки вторым оба слышат друг

- **Автотест:** `e2e TestRouletteFlow`, `k6/functional/pair.js` (CI).

  2 — в журнале office «… не авторизован (AUTHENTICATED): соединение не принято», в соседях
  его нет; 3 — отказ запускаться: «Master без KONTAKT_JOIN_TOKEN примет кого угодно»;

## Критические

### C-1. Жалоба: жёлтая карточка, затем бан
- **Шаги:** A и B соединены (B-2). В A «Пожаловаться» → «Точно?». Затем A и B снова
  соединить (положить и снять обоим) и снова пожаловаться на B.
- **Ожидается:** после первой жалобы B получает жёлтую карточку и уходит искать дальше, A
  видит «Собеседнику выдана жёлтая карточка»; A и B больше не соединяются друг с другом.
  Вторая карточка B от любого человека — вечный бан: у B нет кнопки «Снять трубку».
- **Автотест:** `e2e TestYellowCardThenBan`.
- **Итог:**

### C-2. Конфиг на лету: режим обслуживания
- **Шаги:** идёт разговор A–B. В `config/kontakt.json` поставить `"maintenance": true`,
  сохранить. Через 2 с в третьем браузере снять трубку. Вернуть `false`.
- **Ожидается:** A–B продолжают говорить; новый звонок отклоняется (503, причина
  `maintenance`); после возврата `false` звонки снова проходят. Перезапуск не нужен.
- **Автотест:** `e2e TestMaintenance`, `TestHotConfigInstantBan`.
- **Итог:**

### C-3. Метрики станции отражают звонки
- **Шаги:** провести один разговор A–B. `curl -s 127.0.0.1:8091/metrics | grep kontakt_` и
  `curl -s 127.0.0.1:8082/metrics | grep kontakt_`.
- **Ожидается:** `kontakt_signal_calls_total{result="accepted"}` ≥ 2, `kontakt_pairs_total` ≥ 1;
  во время разговора `kontakt_media_bridges 1`; `kontakt_media_bytes_*_total` растут между
  двумя запросами. Отказы (`banned`, `maintenance` …) видны нулями до первого события.
- **Автотест:** `e2e TestMetricsReflectCall`.
- **Итог:**

### C-4. Master вернулся — Worker'ы регистрируются сами

- **Ожидается:** все живые Worker'ы снова в реестре **не дольше чем через 30 с** (пауза между

### C-6. Граф системы в Grafana
- **Шаги:** Grafana → дашборд «Kontakt Mesh», «Глазами узла» = `master · master`. Затем убить

- **Ожидается:** все узлы с именами, Master синий, рёбра данных зелёные, синий пунктир к
  Master'у; убитый Worker через ~15 с красный, с красным пунктиром к Master'у, сводка
  «OFFLINE 1»; без Master'а граф виден глазами Worker'а (его окрестность).

### C-10. Настоящая сеть: Worker на другой машине
- **Шаги:** на втором устройстве (ноутбук или телефон в Termux) запустить Worker:
  `KONTAKT_JOIN_TOKEN=demo bin/kontakt-node -role worker -name phone -listen 0.0.0.0:7417 -advertise <его IP>:7417 -admin 127.0.0.1:7427 -master <IP первой машины>:7400 -master-key <ключ>`.
  Mesh-демо на первой машине должен слушать не только localhost — для этого кейса запустите
  Master и один Worker вручную с `-listen 0.0.0.0:…` и `-advertise <IP>:…`.
- **Ожидается:** узел в реестре, ребро к нему с реальным RTT (миллисекунды Wi-Fi, не
  микросекунды), на графе зелёное; при выключении Wi-Fi на телефоне — OFFLINE через ~15 с.
